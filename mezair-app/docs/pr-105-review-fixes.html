PR #105: review fixes

9 November 2026 · Chat experience PR

The changes address 67 inline review threads (one contains two findings), additional review-summary findings, thirteen test suggestions and independently verified recovery and streaming issues. The PR remains open for the owner to merge.

File recovery and Git safety

  • Rewind requires a durable undo snapshot for every affected repository before changing files. Failed snapshot persistence stops the operation and removes its unrecorded refs.
  • Concurrent rewinds and new managed turns are fenced by canonical checkout path, including aliases and nested repositories. Active turns are rechecked before mutation.
  • If a file operation fails after rewind begins, the UI retains a usable Undo action and reports the incomplete operation.
  • Submodule working files have their own pinned snapshots. Rewind preserves the parent and child index, branches and HEAD. Initialization and topology must match; unsupported legacy snapshots fail explicitly. Nesting and snapshot count are bounded.
  • Review actions use the displayed repository snapshot. Stale hunk fingerprints fail closed, mutation errors remain visible, and unstaging a rename includes both paths.

Delayed follow-up review

  • Checkpoint capture, rewind, whole-file discard and hunk discard share canonical checkout leases. A capture cannot retain partially restored files.
  • Provider send preparation reserves its session before awaiting work. Simultaneous idle follow-ups queue in order; failed preparation releases the reservation.
  • Git whole-file actions use literal paths, parsed diffs disable forced color, and staged renames require whole-file unstaging so their source deletion cannot be left behind.
  • Verification busy state and completion belong to the transcript store and survive panel remounts. A remount cannot resubmit in-flight verification commands.
  • Inline edits stay mounted while the thread is busy. Retained attachments make a request sendable even with empty text, including through the real ChatView action queue.
  • A successful mutation refreshes the displayed repository even when manual Refresh races its completion. Closed panel controls retain an enabled keyboard tab stop.
  • Delivery timestamps survive uncertain retries and subsequent status events.
  • Failed actions recover only into their original workspace, thread and persona composer. A browser regression exercises the real ChatView editor, fork, send failure, thread switch, attachment recovery and the other conversation's persisted draft.
  • The earlier durable cleanup queue and stop-on-incomplete-rewind behavior also address the follow-up review's cleanup and partial-rewind findings.

The four additional test suggestions cover distinct enqueue/delivery timestamps, empty and model-only usage, a zero-sized context meter, failed resend through ChatView, and undo after a successful file removal followed by a second operation failure.

Additional findings in the review summary

  • Whole-file discard uses a fingerprint of the reviewed patch, reverses that patch through Git, and refuses newer edits. It is disabled while the agent is working. Untracked deletion is protected by the same reviewed-content check.
  • Every repository needs a durable undo snapshot before rewind; partial failures retain a usable recovery key.
  • Undo is associated with its source workspace and cannot appear or run from another workspace. It opens a file preview before applying.
  • Rewind, undo and edit/resend confirm the current file set through a main-process tree fingerprint. Changed files refresh the preview and require another confirmation. The service rechecks all contents after saving undo and before its first write.
  • Recovery leases and active-session checks use canonical execution paths, including shared checkouts, nested repositories and retained repair worktrees.
  • Checkpoints persist the validated execution path. Capture, preview, rewind and undo use the retained repair worktree; unavailable or mismatched bindings fail without falling back to the ordinary checkout.
  • Content-hunk patches exclude executable-bit changes. Current-selection keys prevent stale hunks acting on another file; diffs and checkpoint restore use literal paths.
  • Schema 121 retains Git-ref cleanup metadata transactionally before checkpoint rows cascade away. Cleanup runs at startup and in bounded background batches, retries offline checkouts, and checks the expected ref value before deletion.
  • Current conversation repository scope and workspace membership are validated before preview reads and independently before restore changes files.

Real-Git and SQLite regressions cover stale previews, edits during undo capture, removed workspace membership, indirect deletion, executable-bit preservation, reviewed deletion, repair-worktree recovery, the oldest retained checkpoint, and upgrades from schema 120.

Latest review: recovery boundaries and interaction details

  • Thread deletion, local and synced workspace deletion, repository removal and ref cleanup share recovery leases. Undo metadata stays intact during a rewind.
  • Normal and queued captures use the provider session's actual repository bindings. Stale bindings fail closed; the UI starts a fresh idle session when repository selection changes. Active-session exclusion includes the execution cwd for repository-free workspace chats.
  • Offline secondary checkouts are skipped during best-effort capture while explicit bindings still validate current membership.
  • Schema 122 stores independent child-ref manifests. Cleanup survives a missing parent ref, preserves legacy paths before forgetting a repository, and advances past unavailable rows. Retention uses insertion order so clock changes cannot immediately prune a new Undo.
  • Git review forces three context lines, uses the displayed no-index patch for untracked hunks, terminates hanging Git/filter process groups, refuses parent-level submodule discard, and fences checkout-changing branch operations.
  • Both file and hunk discard are disabled during active work. Rewind and Undo invalidate and refresh the open Review panel immediately.
  • First-message edits carry the explicitly created thread ID. Composer recovery queues all failed actions and acknowledges each after applying it. Reuse and event handlers follow the active conversation; work-item layout keeps its own scope.
  • Arrow keys continue from the focused option after a panel closes. Regressions cover disabled selected options and confirm the actual repository IDs used by delayed mutations.
  • Rendered checks fail on uncaught browser exceptions. The expanded suite passed 70 assertions across wide and narrow layouts, including the real ChatView first-message edit and multiple-action recovery.

Final review follow-up

  • Ordinary sends reserve their session before checkpoint or local-reply preparation. Follow-ups queue during preparation and settle after local replies, provider delivery or failure.
  • Explicit scaffold and headless Mesh execution roots remain valid without repository IDs. Repo-bound sessions retain path-cardinality validation and canonical Windows assertions.
  • Git pull, branch creation, checkout and merge have bounded subprocess lifetimes. Discard checks overlapping active conversations in main while holding the same lease that blocks new turns.
  • Quarantined workspace projection and binding changes now commit together. A busy recovery lease retains the original sealed update and schedules retry.
  • Forks carry their source thread and respect navigation; replacement sessions stop before installing themselves in another conversation. A blocked /new retains its text.
  • Recovery retains overflow attachments, blocks incomplete submission and acknowledges text separately so navigation cannot append it twice. Scoped attachment metadata survives composer remounts. Deleted destinations release queued payloads after checking the local thread catalogue.
  • Rendered assertions check request ordering, both discard controls and exact mutation destinations. Service regressions check that stale sends never capture and real mutation entry points preserve Undo while leased.

Security finding: current workspace membership

Outcome: implementation complete; final CI verification pending. A ready session could receive a new writable turn after its repository left the workspace: checkpoint capture rejected the repository, but its best-effort error was swallowed. The shared send boundary now checks current membership independently of snapshots, including after asynchronous ACP acknowledgements. Guides, feedback, local output, live tool context and accepted pending answers/approvals use the same current grant. Denial and cancellation remain available.

Scope and limits

Checkpoints cover local normal chats, prepared tasks and delivered queued turns. Temporary chats and read-only side questions remain excluded. Repository leases coordinate Mezair-managed operations; they are not operating-system filesystem locks. Submodules must be initialized and retain their recorded layout. No new provider permissions are granted.
