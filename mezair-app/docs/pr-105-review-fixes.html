PR #105: review fixes

8 November 2026 · Chat experience PR

The changes address all twenty inline review findings, the additional findings in the review summary, two test-only suggestions, and the independent rewind safety finding. The PR is intentionally left open for the owner to merge.

File recovery and Git safety

  • Rewind requires a durable undo snapshot for every affected repository before changing files. Failed snapshot persistence stops the operation and removes its unrecorded refs.
  • Concurrent rewinds and new managed turns are fenced by canonical checkout path, including aliases and nested repositories. Active turns are rechecked before mutation.
  • If a file operation fails after rewind begins, the UI retains a usable Undo action and reports the incomplete operation.
  • Submodule working files have their own pinned snapshots. Rewind preserves the parent and child index, branches and HEAD. Initialization and topology must match; unsupported legacy snapshots fail explicitly. Nesting and snapshot count are bounded.
  • Review actions use the displayed repository snapshot. Stale hunk fingerprints fail closed, mutation errors remain visible, and unstaging a rename includes both paths.

Additional findings in the review summary

  • Whole-file discard uses a fingerprint of the reviewed patch, reverses that patch through Git, and refuses newer edits. It is disabled while the agent is working. Untracked deletion is protected by the same reviewed-content check.
  • Every repository needs a durable undo snapshot before rewind; partial failures retain a usable recovery key.
  • Undo is associated with its source workspace and cannot appear or run from another workspace. It opens a file preview before applying.
  • Rewind, undo and edit/resend confirm the current file set through a main-process tree fingerprint. Changed files refresh the preview and require another confirmation. The service rechecks all contents after saving undo and before its first write.
  • Recovery leases and active-session checks use canonical execution paths, including shared checkouts, nested repositories and retained repair worktrees.
  • Checkpoints persist the validated execution path. Capture, preview, rewind and undo use the retained repair worktree; unavailable or mismatched bindings fail without falling back to the ordinary checkout.
  • Content-hunk patches exclude executable-bit changes. Current-selection keys prevent stale hunks acting on another file; diffs and checkpoint restore use literal paths.
  • Schema 121 retains Git-ref cleanup metadata transactionally before checkpoint rows cascade away. Cleanup runs at startup and in bounded background batches, retries offline checkouts, and checks the expected ref value before deletion.
  • Current conversation repository scope and workspace membership are validated before preview reads and independently before restore changes files.

Real-Git and SQLite regressions cover stale previews, edits during undo capture, removed workspace membership, indirect deletion, executable-bit preservation, reviewed deletion, repair-worktree recovery, the oldest retained checkpoint, and upgrades from schema 120.

Scope and limits

Checkpoints cover local normal chats, prepared tasks and delivered queued turns. Temporary chats and read-only side questions remain excluded. Repository leases coordinate Mezair-managed operations; they are not operating-system filesystem locks. Submodules must be initialized and retain their recorded layout. No new provider permissions are granted.
