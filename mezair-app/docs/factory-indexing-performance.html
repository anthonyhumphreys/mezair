Faster drafts, smaller indexing requests

Desktop performance changes · 6 November 2026

Factory drafts now use the app’s configured provider and model, with a bounded foreground slot, progress and cancellation. Repository enrichment uses one background inference at a time and summarises up to four modules per request.

What changed

  • Missing repositories or compatible saved workflows fail before inference. Draft requests contain workflow identifiers and descriptions, rather than full workflow graphs.
  • Organisation discovery no longer blocks a draft. Recent account-scoped editor choices are optional context; save and activation still check current permissions.
  • Codex receives the selected model explicitly, with medium reasoning for drafts and low reasoning for enrichment. Azure retains its configured deployment. Codex and Claude data generation use isolated temporary directories without repository tools or project context.
  • One foreground utility call can run alongside one background call. Each lane has a bounded queue. Draft deadlines include queue wait and retries; cancellation reaches API requests and CLI process trees.
  • CLI output and diagnostic tails are bounded. Cancelled calls retain their scheduler slot until provider cleanup settles.
  • Enrichment reads at most three 1,500-byte file prefixes per module and caps directory context. Completed batches persist progressively; failed batches retain retryable hashes.
  • Successful unchanged module summaries and overviews are reused. Cache identity includes the provider, configured model and prompt version. Summary metadata records that identity instead of a hardcoded older model.

Validation and limits

Local validation: 3,645 tests passed (12 existing skips), lint and both Desktop TypeScript checks passed. Production main/preload/renderer and headless daemon builds also passed.

Regression coverage includes queue isolation and resource limits, queued and active cancellation, cross-window IPC ownership, model selection, invalid or incomplete batch output, stale draft responses, UTF-8 file prefixes, model-change invalidation and failed-batch retries.

A live synthetic Codex request returned valid summaries for two modules in 7.256 seconds using GPT-6.1 Sol with low reasoning. Safari checks exercised successful draft completion, visible progress and cancellation with the prompt retained.

This is not an end-to-end production latency or memory benchmark. Input and call-count reductions are measured; elapsed improvements on real repositories still depend on provider load, model and response length. Reduced context trades exhaustive file detail for concise module responsibilities. The structural repository map still finishes first, independently of AI enrichment.
