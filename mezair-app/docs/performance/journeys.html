03 / CHANGES

What changed in each journey.

CHAT · PRIMARY FOCUS

Stop rebuilding completed work.

  • A transcript-local composer only recomposes turns whose immutable entries or live state changed; it retains one history rather than caching every visited thread.
  • Memoized turn rows preserve expanded processing state. File-change and later-edit guards stay current when a later turn changes a file.
  • Collapsed routine work is unmounted. Questions, approvals and other surfaced interactions remain visible.
  • Scroll capture runs once per frame, skips turn geometry at the bottom and avoids identical session-storage writes. Reader position, jump-to-live and reduced motion remain supported.
  • A separate memoized navigation context keeps transcript bytes out of shell, status-bar, activity and palette subscriptions.
FIRST RUN & ONBOARDING

Defer later setup screens.

Agent connection and Sync setup UI load when their steps are reached. The terminal loads at first use and retains its workspace state afterward. Scaffold polling pauses while hidden and refreshes on return.

SETTINGS

Keep connection refreshes controlled.

Cloud-agent connection-progress polling is visibility-aware and waits for the previous request to settle. Sync setup uses the same non-overlapping poller. The existing lazy category loading and unsaved-edit protections remain in place.

SOFTWARE FACTORIES

Bound presentation reads.

Directory and non-selected-factory summary batches each use at most four concurrent reads. Selected-run polling and relative clocks pause while hidden. Navigation fences late responses and skips obsolete queued reads. Authorised daemon execution continues independently.

DASHBOARDS

Coalesce refreshes; reject stale results.

Equivalent in-flight reads share a promise. An explicit refresh can bypass a cached initial read; older responses cannot overwrite it. Polling resumes on visibility, clocks pause while hidden, and workspace/configuration changes invalidate pending results.

Measurement protocol

Chrome/156.0.8078.80; Apple M3; darwin 27.0.0 arm64. Five fresh browser contexts per version, production Vite output, background throttling disabled and reduced motion enabled. Each context renders 100 turns with 30 routine operations per turn, then applies 60 live-answer updates. Heap is collected before and after the scenario; the reported value subtracts the idle heap.

Composition additionally runs 200 updates. Scroll geometry counts use 20 synthetic scroll events at a fixed position. Table values are medians across the five runs. The per-run P95 uses the 60 streamed updates; it is not a field input-latency metric.

What still needs real-device evidence

This fixture does not exercise packaged Electron startup, native processes, whole-app RSS, external providers, network latency, rich surfaces, attachments or large diffs. No live account, factory, Git publication or deployment is exercised. Cold-mount timing is reported separately and should not be read as native startup time.

The full test suite initially encountered blocked loopback sockets in the sandbox. It passed with local test sockets allowed. The final shell/shortcut changes also passed 111 focused journey tests.

05 / NEXT

Ten steps to improve further.

Ordered work for the next pass, with a concrete outcome for each step.

  1. 01

    Measure native startup and whole-app memory

    Record cold launch, time to interactive, idle RSS and a 30-minute streaming soak in the packaged Electron app on Apple Silicon and Windows. Set device-specific budgets before the next release.

  2. 02

    Window long transcript histories

    Mount only nearby completed turns, while retaining selection, keyboard navigation, search and saved anchors. Target a bounded DOM for 1,000-turn histories instead of growth with every turn.

  3. 03

    Render streaming Markdown in stable blocks

    Reuse settled paragraphs and code fences inside the live answer. Benchmark long code, tables and incomplete fences; aim for P95 update work below 8 ms on the reference machine.

  4. 04

    Move highlighting off the UI thread

    Use one cancellable worker, deduplicate language loads, and discard obsolete results. Exercise multiple code blocks streaming together and keep the existing byte-bounded cache.

  5. 05

    Page stored histories and factory runs

    Add cursor-based chat history and a factory summary endpoint so rails do not fetch full run histories. Measure IPC bytes, SQLite time and peak allocation with large workspaces.

  6. 06

    Narrow the remaining chat subscriptions

    Separate composer commands, model preferences, artifacts and live execution state. Profile background chat while editing Settings and require unrelated views to stay idle between status transitions.

  7. 07

    Share dashboard reads across modules

    Deduplicate equivalent queries across panels and cap expensive source refreshes in the main process. Preserve per-workspace keys, explicit cache bypass and stale-success fallback.

  8. 08

    Warm likely tools on user intent

    Preload the terminal, palette or next setup step on focus or hover after the shell is ready. Measure first-use latency and keep speculative loading out of the critical startup path.

  9. 09

    Audit rich-surface resource release

    Soak-test diagrams, large diffs, document previews, images and pop-outs. Release observers, object URLs, workers, WebGL contexts and retained artifact bytes when their owners close.

  10. 10

    Gate regressions in CI

    Run this fixture and large/rich variants on a pinned runner, retain raw samples and compare paired builds. Start with budgets for bundle growth, retained heap, DOM count and streamed P95, then add real-device input latency.
